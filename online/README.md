# 真名之火 · 线上初版

好友房间原型，源码保存在 https://github.com/Moloym00/mythology/tree/main/online ，规则依据上级目录 `玩法书_V1.2.md`。保留现有美术。工程与纸面规则、美术原稿分开，可单独部署和迭代。

## 本地启动

要求 Node.js >= 22.13、npm。首次启动：

```sh
npm ci
npm run db:local
npm run dev -- --host 0.0.0.0
```

Windows 也可双击 `启动开发.bat`。打开终端给出的 Local URL。手机同局域网可访问本机局域网 IP 与相同端口（须系统防火墙允许）；不同玩家使用不同浏览器配置或不同设备。相同浏览器同源的标签页共享座位凭证。

## 日常检查


## 最小架构

一个房间一条 D1 记录，内含游戏状态和参与者身份。客户端每1.8秒取一次公开状态，后台标签页降到7秒，不需要 WebSocket 服务器。所有操作由服务端重新验证。

客户端提交 `revision + actionId`。服务端只接受该版本的合法选项，再以 `UPDATE ... WHERE revision = ?` 原子写入。两个并发请求只有一个成功，另一个收到409；UI等待刷新后让玩家重新选择，不自动重试行动。

加入时生成高熵 bearer token，浏览器本地保存，服务端仅保存 SHA-256。邀请链接只含房间号，不含身份凭证。手牌、待选记忆及风暴预览只向所属玩家提供；随机种子、牌堆顺序和身份哈希不返回客户端。浏览器本地数据清除后无法自动认领旧座位。

房间每次行动延长7天有效期，读取不续期。目前通过过期字段禁止读取；物理清理留给后续定时维护。正式开放公共访问前应补充创建/加入限流及容量治理。

## 决策反馈与氛围（2026-09-08）

牌桌显示当前计分分项、守夜奖励进度和有限后备神说明。选择行动后可查看代价与结果预告；结算后显示得分、心智、手牌、风化、新神到来等变化，并保留当前页面最近12次变化供回看（刷新后重新记录，完整过程仍看游戏日志）。多人快速操作时，一次刷新可能汇总多个动作。

新神入场有轻量动画，遵循系统减少动态效果设置。“开启氛围音”由玩家主动点击，播放本地合成和弦与结算提示音，切到后台暂停；这是轻量音效版本，尚非完整配乐。基础出牌仍使用筛选与选择框，未完成全套卡牌交互和美术演出。

本地AI开始根据公开局面使用有收益的神恩，保留手牌不足时的跳过选项。自动检查覆盖规则、反馈与整局结束，不代表玩法已完成平衡验证。

## 发布与后续接手

Sites 配置位于 `.openai/hosting.json`，D1绑定名为 `DB`。此项目使用 Workers 服务端，不能直接作为静态文件放到 GitHub Pages。

`npm run build` 生成 Worker 与静态资源，Sites 插件同时带上 `drizzle` 迁移。`wrangler.local.json` 仅用于本地数据库初始化，不是线上配置。迁移修改用 `npm run db:generate`，不要直接改已经发布的 SQL 迁移。

当前约定：先使用 GitHub 保存源码与继续开发，后续考虑腾讯云上线。不继续尝试 Sites 发布。已有 Sites 配置仅作为当前构建所需的历史配置保留，不表示已上线。

腾讯云迁移时，规则核心和界面可以复用；需要把 `cloudflare:workers`、D1 存取和 Workers 构建入口适配为目标服务。静态页面托管本身不足以运行多人房间，须配套服务端及数据库。具体腾讯云产品与部署方案尚未确定，不提前绑定。

尚未做真实浏览器交互/视觉验收及真人联机体验验收。不要把接口检查和自动流程检查描述成已通过真人试玩。后续先完善点击出牌流程与移动端操作，再加房间管理，最后按需要扩展功能。

## AI 玩家（2026-09-08 新增）

打开本地页面 → 建房 → 点击两次“添加AI” → 选择“本地AI · 免费” → 开始守夜。可以增加到6人，也可以与真人混合。已有游戏中不能插入AI，需新建房间。AI按回合自动行动，合诵、严寒、神恩选择、弃牌整理都支持。保持至少一个真人页面打开；无人在线时对局暂停，重新打开继续。

本地AI是基于公开局势的启发式策略，不使用大模型、无需API、不会产生接口费用。它和真人使用相同的合法行动列表与信息视图，不能查看其他人的手牌或牌库顺序。它不是经过平衡训练的高水平对手。

### 使用 API / 反代

1. 将本目录 `.dev.vars.example` 复制为 `.dev.vars`。
2. 填写 `AI_BASE_URL`（如服务商给出的 `https://.../v1`，也支持完整 `/chat/completions` 地址）、`AI_MODEL` 和 `AI_API_KEY`。本地免鉴权接口可以留空密钥。这里的反代是兼容 API 的 HTTP 服务地址，不是 SOCKS/HTTP 网络代理端口。
3. 重启开发服务，让服务端读取配置。
4. 在开局前选择“API / 反代”。这会把该 AI 能看到的牌桌和自己的手牌发给你配置的服务，并可能按该服务费率计费。无须把密钥发到聊天中。

接口按 [Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat)发送 `model`、`messages`，读取 `choices[0].message.content`。模型仅返回候选动作的id；不执行模型代码或文本指令。每次最多提供50个去重候选。只有一个选项时不调用模型。超时8秒、错误或非法回复时，本地AI接管该步，界面显示状态；未配置地址或模型时也回退本地模式。

密钥只从服务端环境读取，不进入房间数据库、前端或Git。`.dev.vars*` 已排除版本控制，示例文件仅含占位值。线上迁移腾讯云时配置同名环境变量即可复用调用层，但仍需适配既有数据库/运行入口。

并发：AI调用前使用数据库revision抢占15秒租约，多标签页不会同时请求同一步。玩家动作使旧版本失效时，旧AI结果丢弃；进程异常时租约自动过期后可恢复。前台每次轮询推进一个AI子步骤，不自动为真人出牌。
